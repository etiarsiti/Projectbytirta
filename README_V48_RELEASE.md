# MoonXprojecT V48 — Attendance Security Release

V48 hardens the ESS attendance flow without changing the existing frontend RPC signatures.

## What changed

- Attendance timestamp is generated by PostgreSQL using the company timezone (`hris_company_settings.timezone`). Client `p_tanggal` / `p_jam` are retained only for backwards compatibility and are ignored by the RPCs.
- GPS is required when `hris_enterprise_settings.require_gps=true`.
- GPS accuracy is capped by `hris_company_settings.attendance_max_accuracy_meters` (default 100 m).
- Attendance radius is enforced using the Haversine formula when the company attendance latitude/longitude are configured.
- Selfie is required when `hris_enterprise_settings.require_selfie=true` and must be a JPEG data URL within the server-side size limit.
- Clock-out searches today and yesterday, allowing overnight shifts to close the previous business-date record.
- Manual attendance keeps the normal time-order validation; ESS may represent overnight attendance.
- The browser no longer contains a hardcoded fallback Supabase project.
- Admin Settings now exposes attendance latitude, longitude, and maximum GPS accuracy.
- Employee Portal uses Asia/Jakarta for its displayed business date.

## Required after deployment

1. Run `supabase/migration/045_v48_attendance_security.sql` in the target Supabase project.
2. In Admin → Settings → Absensi, set the office **Latitude** and **Longitude**.
3. Set the desired attendance radius in meters (for example 150).
4. Set maximum GPS accuracy (for example 100 m).
5. Verify `require_gps=true` and `require_selfie=true` in `hris_enterprise_settings`.
6. Test clock-in inside and outside the configured radius.
7. Test an overnight shift: clock-in before midnight and clock-out after midnight.

## Environment

The frontend now fails closed when `VITE_SUPABASE_URL` or `VITE_SUPABASE_ANON_KEY` is missing. Configure both variables in the deployment environment.
